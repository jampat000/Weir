# Weir v1.0.0-rc.10

Date: 2026-10-09

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/jampat000/Weir/issues).

This release candidate makes Weir's Logs say what happened in plain words, stops a warning nobody could act on, and makes Weir's folders readable by your other apps again on Docker. It replaces 1.0.0-rc.9, which was tagged but never published: the download of the video tools it was built with had been removed by their publisher.

## What Changed

- **Logs speak plainly.** When Weir can't read a file, Logs now says so in a sentence instead of showing the media tool's own output. The technical detail is still there when you open the entry.
- **A failed job says why.** A job that fails because a file can't be read now says that, instead of "The job hit an unexpected error".
- **No warning at every start.** Weir no longer warns about `WEIR_CORS_ORIGINS` each time it starts. Setting it is optional extra hardening for sign-in; Weir already protects sign-in and saves without it.
- **Docker keeps saved keys under their own secret.** A Docker install now makes a separate secret for the keys you save for your media managers and download clients, the first time it starts. Keys you saved before still open.

## Fixes And Stability

- **Docker: Weir's folders are readable by your other apps again.** When Weir wrote its own secret files on start, it also left a setting behind that made every folder it created private to Weir's own user. So Plex, Jellyfin or another container couldn't read the cleaned files. This happened on any Docker install that doesn't set `WEIR_SESSION_SECRET`. Folders Weir creates now get the usual permissions. If a folder Weir made earlier is still private, you can open it up with `chmod -R a+rX <folder>` on the host.

- Weir now includes a newer build of FFmpeg, the video tool it uses (9.0.2, the same version line as before). Each Weir release also carries copies of the exact tool files it was built with, so a future release can't be held up when the tool's publisher removes an old download.

## Upgrade Notes

- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept.
- Docker: change the image to `ghcr.io/jampat000/weir:1.0.0-rc.10`, then `docker compose pull && docker compose up -d`.

## Docker

- `ghcr.io/jampat000/weir:1.0.0-rc.10`
- Images are published for `linux/amd64` and `linux/arm64`, and run the .NET build of the Weir server.
