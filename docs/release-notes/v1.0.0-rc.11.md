# Weir v1.0.0-rc.11

Date: 2026-10-09

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/jampat000/Weir/issues).

This release candidate makes the update check dependable on busy networks, gives the Windows tray the same look and menu as Deluno's, stops Weir slowing down while it processes, and settles three cases that used to leave a file waiting or showing an error.

## What Changed

- **The update check keeps working when GitHub limits your network.** Weir used to say only "Could not check for updates". It now reads GitHub's public release feed, keeps showing the update it already knew about, and says when it will try again. Addresses #935.
- **The tray's own updater uses the same feed.** Update checks from the tray work again on networks that hit GitHub's limit. Addresses #935.
- **The Windows tray matches Deluno's.** Addresses #939.
  - The icon shows the state: a corner mark appears only when something differs (starting, paused, needs you, or an update is ready), and no mark means all is well.
  - The hover text gives the status, for example "Weir - Paused".
  - The menu is the one Deluno's tray uses.
  - You can pause and resume processing from the tray.
  - Windows asks once whether Weir should start when you sign in. Nothing is switched on without your answer.
  - Weir no longer opens your browser by itself when it starts. A notice offers to open Weir, and clicking it does.
  - If Weir is already running, starting it again shows a notice, and clicking the notice opens Weir.
- **A first visit no longer says "Your session expired".** On a fresh install, the first page goes straight to creating your account. The line with your setup code is now logged as ordinary information, not a warning. Addresses #937.
- **"Process again" on a file Weir already cleaned now answers.** It shows "Skipped: already done" in Activity, instead of doing nothing visible. A file that has changed is still processed. Addresses #936.
- **A file deleted while it waits settles quietly.** After a short second look and the usual 10-minute wait, Weir records "no longer there" and moves on, with no errors and no failed job. A file Weir can't read is never handed back as unchanged. Deluno is told the file is gone. Addresses #940.
- **A finished hand-off no longer waits for ever.** When the main film was delivered and only an extra was skipped for being under the size minimum, the hand-off now ends completed. Weir also accepts the media manager's "imported" for it, so the entry settles instead of staying on "Waiting for your media manager". Addresses #941.

## Fixes And Stability

- **Weir no longer slows to a crawl while it processes files.** Logs could show a warning about "thread pool starvation" and pages and live updates went slow. Database writes now queue without holding up other work, and long file copies run on their own threads. Addresses #938.
- **Installing Weir quietly over a running Weir starts it again.** A silent Setup, which is how Deluno updates Weir, used to leave Weir stopped until someone started it by hand. Weir now starts again by itself, without opening a browser. A Weir that was stopped before stays stopped. Addresses #942.
- Several tests that failed now and then for no real reason are fixed at the root, so a failed check means something.
- Weir's golden-path and tray-standard documents are now word-for-word copies of Deluno's, so the two apps follow the same rules.

## Upgrade Notes

- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept, and so is your choice about starting Weir when you sign in to Windows. A fresh install asks once.
- Docker: change the image to `ghcr.io/jampat000/weir:1.0.0-rc.11`, then `docker compose pull && docker compose up -d`.

## Docker

- `ghcr.io/jampat000/weir:1.0.0-rc.11`
- Images are published for `linux/amd64` and `linux/arm64`, and run the .NET build of the Weir server.
