# Weir v1.0.0-rc.12

Date: 2026-10-09

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/jampat000/Weir/issues).

This release candidate makes the tray's dot show only whether Weir itself is healthy, stops an extra that was left out for being too small from counting as needing you, settles a file that leaves before Weir starts on it, and makes the first-run port window impossible to miss.

## What Changed

- **The tray's dot shows Weir's health, nothing else.** Addresses #944.
  - Green: Weir is running and everything it relies on answers.
  - Amber: Deluno, or a watched, work or output folder, isn't answering. A network drive that hangs counts after about 10 seconds, and only after two misses in a row, so a single slow answer doesn't turn the dot amber.
  - Red: Weir has stopped.
  - The dot blinks while Weir is starting.
  - Pause bars and the update arrow now sit in the opposite corner. If both apply, the pause bars show.
  - The hover text and the menu's status line read "Weir - ..." and say what is wrong, for example "Weir - Deluno isn't answering".
  - Files waiting no longer change the tray at all. They stay on Weir's own screens.
  - **Start with Windows** is asked once if an older version switched it on without asking. The tick beside it in the menu is now announced by screen readers.
- **An extra left out for being under the workflow's minimum size is no longer something you need to act on.** Addresses #945.
  - It reads "Skipped" and no longer counts under **Needs you** or in the Dashboard headline.
  - If the workflow deletes such files, it reads "Removed: under the workflow's minimum size."
  - Other rule skips (maximum size, patterns, date windows) still ask you.
  - No skip is ever shown or counted as cleaned.
- **Just finished shows each file's current result.** A film that was imported after an earlier failure no longer shows "Couldn't finish". The Dashboard headline and chart agree with it. Addresses #945.
- **A file that leaves before Weir starts on it says so at once.** Addresses #946.
  - While waiting to settle, while paused or outside workflow hours, the file now reads "... is no longer there" instead of "Waiting...". It is recorded once, not twice.
  - The panel of a file that is gone offers only **Remove from list**.
  - A file placed directly in the watched folder no longer logs a cleanup warning.
- **The first-run port window opens in front.** Addresses #947.
  - It stays on top until you answer, and the tray icon shows while it waits, so Weir never sits silently waiting on a question hidden behind other windows.

## Fixes And Stability

- **A busy PC no longer fails a good clean.** Weir now gives ffmpeg up to 60 seconds to close after it has written a file, instead of 5.
- **No log lines are lost while old logs are trimmed.** A gap introduced in rc.11 is closed.
- Several tests that failed now and then for no real reason are fixed at the root, so a failed check means something.
- Weir's tray standard is a word-for-word copy of Deluno's, so the two apps follow the same rules.

## Upgrade Notes

- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept, and so is your choice about starting Weir when you sign in to Windows. A fresh install asks once.
- Docker: change the image to `ghcr.io/jampat000/weir:1.0.0-rc.12`, then `docker compose pull && docker compose up -d`.
- Two small database changes run on the first start: one adds the kind of file skip, and one adds an index that keeps Activity quick. Neither needs anything from you.

## Docker

- `ghcr.io/jampat000/weir:1.0.0-rc.12`
- Images are published for `linux/amd64` and `linux/arm64`, and run the .NET build of the Weir server.
