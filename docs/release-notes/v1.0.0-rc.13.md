# Weir v1.0.0-rc.13

Date: 2026-10-10

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/jampat000/Weir/issues).

This release candidate lets you check for, download and apply an update from System › About without waiting for the tray, saves a checked copy of Weir's data before every update, and stops a frozen ffmpeg after 10 minutes without progress instead of a flat hour. It also lets a media manager leave files under a workflow's minimum size out of a hand-off.

## What Changed

- **Update from System › About without waiting for the tray.** Addresses #950.
  - **System › About › Updates** now has **Check now**, **Download update** and **Restart and apply**.
  - **Check now** makes the tray look for an update at once, and the page shows the result as it happens.
  - **Download update** works in every update mode, Notify only included, because clicking it is your choice. The page shows "Downloading update..." and then the ready state.
  - **Restart and apply** restarts Weir, installs the downloaded update, and the page reloads by itself.
  - The next step is the blue button. Each button is only available when it applies.
  - When the tray isn't running (Docker, or the tray was quit), the buttons are greyed out with a plain reason beside them.
  - **Download installer** and **Release notes** stay as small links.
- **A checked copy of your data before every update.** Addresses #951.
  - Before installing an update, the tray asks Weir to save a checked copy of its database, settings and keys in the backups folder. The last 5 copies are kept.
  - If the copy can't be made, for example because there isn't enough free space, the update isn't installed. Weir keeps running the old version and says why on About and in the tray.
  - Weir also takes a copy at start-up when it finds its version has changed. That covers installing Setup over the top and Docker image changes.
  - **System › About** shows where the copy was saved.
- **Minimum file size shared with Deluno.**
  - Weir tells Deluno each workflow's minimum file size, so Deluno knows which files Weir will leave alone.
  - When Deluno sends the list of source files to hand off, Weir leaves out files under the minimum. They are never touched and stay where they are for seeding.
  - This needs a Deluno build with Deluno #1199.

## Fixes And Stability

Addresses #948.

- **A frozen ffmpeg is stopped after 10 minutes with no real progress.** It used to run until a flat 1-hour or size-based limit. A big remux on a slow NAS is no longer killed by a flat hour, as long as it keeps moving.
- **An ffmpeg that finishes but won't exit is given a minute.** If its output checks out after that, the clean counts.
- **The same file is no longer processed twice.** A database hiccup could make a job lose its claim and be picked up again. That can't happen now.
- **The tray waits sensibly.**
  - On Quit and on update, the tray gives Weir 45 seconds to stop and shows "Weir - Stopping...", but stays within the installer's time limit.
  - A server that never answers goes red after about a minute. A slow one may take up to 5 minutes.
  - A slow Setup no longer stops Weir coming back.
- A tray test that failed now and then is fixed at the root, so a failed check means something.

## Upgrade Notes

- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept, and so is your choice about starting Weir when you sign in to Windows.
- Docker: change the image to `ghcr.io/jampat000/weir:1.0.0-rc.13`, then `docker compose pull && docker compose up -d`.
- The first update to rc.13 is protected by the copy Weir takes at start-up when the version changes. Later updates are protected by the copy taken before installing.
- Docker's healthcheck start period is now 5 minutes, to leave room for the copy Weir takes at start-up.
- Handing off only the files above a workflow's minimum size needs a Deluno build with Deluno #1199.
