# Weir v1.0.0-rc.5

Date: 2026-10-08

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/jampat000/Weir/issues).

This release candidate lets Deluno check the folder each of Weir's workflows watches. It also brings everything from 1.0.0-rc.4, which was tagged but never published: its Docker build could not finish while Ubuntu's package mirror was slow. If you are on rc.3, all of the changes below are new to you.

## What Changed

- **Deluno can check Weir's watched folders.** Weir's list of workflow folders now says which media-manager library each workflow was set up from, and whether that manager keeps its folders up to date. Deluno uses it to check that each library's downloads land where Weir is watching, instead of showing "Not reported by the processor" on its Health page.

## From 1.0.0-rc.4

- **Pause means pause.**
  - While Weir is paused, nothing touches a media file. Work already running may finish.
  - **Keep looking for new files while paused** only finds files; it no longer finishes anything for them.
  - Files your media manager hands over while paused wait, and are cleaned once when you resume.
  - Weir now checks the pause a second time just before any job starts, so a job can never run while paused.
- **Pauses are recorded.** Pausing, resuming and a pause running out are written to **Activity**, with who and when.
- **Each file is cleaned once.**
  - If a media manager hands Weir a file it already cleaned (the same file, unchanged), Weir doesn't clean it again. It answers as before with the copy it already made, and Activity says **Skipped: already done** (or **already imported** once your manager has collected it). It never counts as a failure, so your manager never blocklists a good release because of it.
  - A changed or new file, such as an upgrade, is cleaned as normal.
  - To re-clean what is already in your library after changing your rules, use **Library cleaning** on the Library page.
- **Weir tells you when a Deluno library stops using it.** If a library in Deluno is no longer set to Refine before import, or is removed, Weir leaves its workflow exactly as it is and says so in **Activity**, with what you can do next.
- **Workflows you linked to Deluno yourself are kept in step too.** A workflow linked to Deluno by hand with exactly the folders Deluno reports is now taken over by the automatic set-up, instead of Weir trying to make a second one ("Weir could not set up Movies from Deluno").

## Fixes And Stability

- Changing **Keep looking for new files** through the API during a timed pause no longer turns it into "until you resume".
- **Activity shows what a cleaned file saved** when the original was kept, as it is for any workflow linked to a media manager. Before, those files showed no sizes and read "handed back as it was". Files cleaned before this update show **Not recorded**.
- Every kind of Activity entry has a proper title, instead of words taken from its internal name.
- Weir no longer looks a title up a second time when it is needed before any file has been matched to it.

## Upgrade Notes

- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept.
- Docker: change the image to `ghcr.io/jampat000/weir:1.0.0-rc.5`, then `docker compose pull && docker compose up -d`.

## Docker

- `ghcr.io/jampat000/weir:1.0.0-rc.5`
- Images are published for `linux/amd64` and `linux/arm64`, and run the .NET build of the Weir server.
