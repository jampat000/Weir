# Weir v3.0.3

Date: 2026-09-20

This release fixes files that a media manager hands to Weir the moment a download finishes being passed along without being cleaned.

## Fixes And Stability

- **A file handed over straight after its download finished is now cleaned.** Weir waits a short time after a file last changed before it touches it (60 seconds unless you changed **Minimum file age**), so it never works on a file that is still being written. A media manager hands a file to Weir within seconds of the download finishing, which is inside that wait. Weir treated "too new" as a failure that could never succeed, so it did not try again: a library set to **Pass through** handed the original on unprocessed, and a library set to **Reject** could tell your media manager that a good release was bad. Weir now puts the file on hold with a reason that says how long is left, looks again by itself once the file is old enough, and only then tells the media manager the result. The wait itself is unchanged.
- This applies to every media manager that hands files to Weir, and to **Check again** and **Try again** in **Files**. Folder scans already waited correctly and are unchanged.
- A file that is still changing after about half an hour is left on hold with a plain reason, instead of being checked forever. Use **Check again** in **Files** when the copy has finished.

## Upgrade Notes

- No settings change and no database change. Nothing to do after upgrading.
- Windows: **Settings → Upgrade** or **Check for updates** in the tray, or install `Weir-win-Setup.exe` over the top.
- Docker: `docker compose pull && docker compose up -d`.
