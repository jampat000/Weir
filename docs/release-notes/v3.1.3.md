# Weir v3.1.3

Date: 2026-09-23

This release stops Weir repeating work it has already done. A file it has cleaned is not cleaned again, a file that has left the watched folder stops being listed, a file it cannot read is not read for ever, and cancelling a queued job now ends the hand-off it belonged to.

## Fixes And Stability

- **A file Weir has already cleaned is never cleaned again.** In a library set to remove the original after cleaning, Weir sometimes has to leave one in place: TV season cleanup waits while another episode of that season is still queued, or while no media manager can be asked, and a movie's release folder can be locked. Every scan then cleaned that file again and handed it back to your media manager again, every five minutes. Weir now recognises the file its last successful pass cleaned in every library, not only in one set to keep originals. A movie whose removal was interrupted is still finished once the lock clears. (#644)
- **A file that leaves the watched folder stops being listed.** A download removed by your download client, or deleted by hand, before Weir finished with it stayed in the list for ever — as waiting, on hold, or stuck, with nothing to act on. Once it has been gone for ten minutes, Weir forgets it and says so in Activity. Files it has finished with stay as history, and nothing is forgotten while the watched folder cannot be read. (#645)
- **A file Weir cannot read from start to finish is not read for ever.** Reading a file right through is how Weir tells a download that is still arriving from a damaged one. A file that failed that read was looked at again on every scan — gigabytes of disk reads every few minutes — and nobody was ever told. Weir now looks again after 5, then 15, then 45 minutes, and only while the file is unchanged. A file that has not changed through all three is damaged rather than unfinished, so the library's failure policy decides what happens to it, as it does for any file Weir cannot process. (#646)
- **Cancelling a queued job ends the hand-off it belonged to.** Cancel on the Jobs screen changed the job and nothing else: the media manager that sent the file went on being told "queued" and could never end its own record, and the file itself read "Waiting" for ever. The file now reads **Cancelled**, a state Weir leaves alone until the file changes or you queue it again from Files, and the hand-off ends as cancelled, so the manager hears it. A hand-off of several files whose others were delivered still reports completed. (#643)

## Upgrade Notes

- No database changes: 3.1.3 opens a 3.1.2 database as it is.
- Windows: **Settings → Upgrade** or **Check for updates** in the tray, or install `Weir-win-Setup.exe` over the top.
- Docker: `docker compose pull && docker compose up -d`.
