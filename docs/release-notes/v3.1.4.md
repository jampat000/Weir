# Weir v3.1.4

Date: 2026-09-23

This release is the new display. **Live** replaces Home as the first screen and shows processing as it happens; **Library** is its own screen for the files already on your storage; **Settings** holds everything you configure. The Library file panel gains two things the rules cannot do for you: choosing the tracks for one file yourself, and telling Weir to leave a file alone.

## The New Display

- **Live is the first screen.** What is being worked on now, which step each file is at, how fast it is going and what is coming out of it, beside what finished and what needs a person. It fits one screen at every width from a phone to 2560 px, and nothing scrolls sideways.
- **Library is its own screen.** The title is the library picker — "Library › TV ▾" — so one library needs no chooser at all. One row of chips holds the counts and the filters together, the table groups a library the way you think of it (by title and season), and a file opens a panel that says, track by track, what would go and why.
- **Settings holds everything you configure**, in one row of tabs: General, Libraries, Rules, Media managers, Processing, History and logs, System. Home and Processing's Overview are gone; their addresses redirect.
- **Display density is gone.** Its four steps were 11–13% apart and duplicated what browser zoom already does. The Library list has a **Compact rows** switch instead, which is where density actually meant something.

## Library

- **Choose the tracks for one file yourself.** A file's panel can switch from "decided by this library's rules" to your own Keep/Remove per track, the same way a held download already lets you (#501). It starts from what the rules would do, so you are adjusting an answer rather than starting from nothing. Your choice is checked twice: when you press the button, against the tracks the last scan read — so a choice that cannot apply is refused rather than becoming a job that fails later — and again when the job runs, against a fresh read of the file plus the size it had when you chose. A file that changed in between is left alone and says so.
- **Leave this file alone.** One file, set aside: nothing cleans it — not a scan, not the schedule, not picking it in the table — until you clear it. It survives a rescan, and a job already queued for that file is refused when it reaches the front.
- **"Cleaned" is a real count.** Weir now records when it last cleaned each library file, so the Library screen can say so and let you filter by it, instead of the file quietly turning into "matches your rules" and looking like it was never touched.
- **A clean says what it did.** How many files were queued, and every file Weir would not touch, with the reason. A file you have set aside is left out of the confirmation, so the dialog never counts something it is not going to do.

## Fixes And Stability

- **A library file can be cleaned more than once.** One clean job is kept per file so a second request cannot queue the same work twice — but a *finished* job was answering the next request too, so cleaning the same file again queued nothing while the screen said it had. A rule change, or a hand-picked plan, could not reach a file cleaned any time in the last `WEIR_JOB_ROWS_RETENTION_DAYS`. A finished job no longer stands in the way.
- **A library scan measures what Matroska files would save.** Scans reported "nothing to reclaim" for `.mkv` files even when they would drop several tracks, because the per-track sizes are recorded in tags the estimate never read. Weir now reads them, in order of how much the file actually tells it, and says plainly when a file offers nothing to measure rather than claiming zero. (#648)
- **A disabled button looks disabled.** Buttons Weir had greyed out kept a gold border, a shadow and a pointer cursor, so a button that refused the click looked ready for it.

## Upgrade Notes

- **This release changes the database.** Migration `0012_library_file_marks` adds one table for what Weir has done to each library file — when it last cleaned it, and whether you have set it aside. It runs on first start. A 3.1.4 database cannot be opened by 3.1.3, so take the backup the installer offers if you may want to go back.
- Windows: **Settings → Upgrade** or **Check for updates** in the tray, or install `Weir-win-Setup.exe` over the top.
- Docker: `docker compose pull && docker compose up -d`.
- Nothing a media manager reads has changed since 3.1.3: intake, the hand-off ledger and the hand-off status words are untouched. The processing-file response gains five fields about the pass that is running; existing fields keep their names and meanings.
