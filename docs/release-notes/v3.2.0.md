# Weir v3.2.0

Date: 2026-09-23

This release is the new Weir. **Processing** shows every file as it is worked on, **History** tells the whole story of each file, **Library** is its own screen for what is already on your storage, and **Settings** and **System** are rebuilt so each page does one job. It also fixes several things that looked set up and did nothing, starting with "Keep all subtitles", which removed every subtitle.

## Please check this first

- **"Keep all subtitles" removed every subtitle, in 3.1.3 and earlier.** A profile set to keep all subtitles was read as "keep these languages" with an empty list, so every subtitle track was removed, forced and default ones included. 3.2.0 keeps them. If you rely on that setting, files processed before this upgrade may be missing their subtitles.
- **A library with no rules profile removed every subtitle too.** That is what Weir's built-in rules do. Every library now has a profile: one that had none is given "Movies default" or "TV default", built from exactly the rules it was already using, so nothing changes by itself. Open **Settings › Rules** to see them and change them.

## The new layout

- **Processing is the first screen.** What is arriving, waiting, being worked on and handed back, which step each file is at and how fast it is going, beside what just finished.
- **History** is its own place in the side menu. Every file Weir has touched, filtered by In progress, Finished, Needs you or Failed, by library and by date, with a search. Open a file to see every track kept and removed with the reason in plain words ("French 5.1 E-AC-3 · Not selected — English 5.1 E-AC-3 kept"), its size before and after, and each step of its pass. Try again, Process now, Move to top, Choose tracks, Check again, Why is this held?, Pass through unchanged and Remove from list are all there.
- **Library** is its own screen: the title is the library picker, one row of chips holds the counts and the filters, and a file opens a panel that says, track by track, what would go and why.
- **Settings**: Libraries · Rules · Media managers · Performance · Cleanup · Schedule · Alerts.
- **System**: About · Backups · Security · Logs.
- **Display density is gone.** Browser zoom does the same thing. Text is a 15px base.
- Old addresses keep working and take you to the new place.

## Library

- **Choose the tracks for one file yourself**, starting from what the rules would do. Your choice is checked when you make it and again when the job runs, so a file that changed in between is left alone and says so.
- **Leave this file alone.** Nothing cleans a file you have set aside until you clear it, and it survives a rescan.
- **"Cleaned" is a real count**, and a clean says what it queued and every file it would not touch, with the reason.
- **Check and clean once a day now runs.** The switch was saved and nothing ever read it. Once a day, inside the library's own hours, Weir checks the library's folders and cleans each file that would change, skipping files you have set aside, files still seeding and files whose media manager would download them again. It asks before it is switched on, because removed tracks cannot be put back, and the Library screen says when it next runs.
- **A library's folders and safety checks are in its editor**, under **Files already in your library**. The redesign had left them on no screen at all.

## Settings

- **Libraries** shows each library's source ("From Radarr", kept in step, or "Added in Weir"), what it watches and hands back to, its rules and an on/off switch. The editor chooses the media manager and **which tool writes files**: the best one for each file (mkvmerge for MKV when it is installed, FFmpeg for the rest) or FFmpeg only.
- **Rules** leads with a live example on a real file, then one line for the profile you are editing, its name and the libraries that use it. **Subtitle order** now orders the subtitles Weir keeps; it was saved and never used.
- **Media managers** says whether each manager is **Answering** or **Not answering**, checked every minute, and which libraries use it.
- **Performance**: Files at once is a row of 1 to 10, and 9 and 10 now save. "Verbose file-detection records" is gone: nothing ever read it. **Keep failed work files** now keeps the copy that failed, in the work folder, until the day-old sweep removes it.
- **Cleanup**: each job has its own switch, how often it runs, last run, next run and Run now. Changes apply within half a minute, with no restart.
- **Schedule**: a week per library showing whether it may start work right now and when that changes, with the hours editor underneath; the time zone, with the time it is there now; and when Weir's own cleanup jobs and settings backup run. The two Movies/TV "watched-folder windows" are gone: they were saved and never read.
- **Alerts**: one tick per event per channel, saved straight away, and events named for what they are.
- Every dropdown is readable in the dark theme. On Windows the open list was pale text on white.

## Media managers and hand-offs

- **Imported libraries are linked to their manager** (#651). Until now no library was ever linked, so Weir could never reject a bad download through Sonarr or Radarr, and every library read "No upstream signal". Libraries imported before are linked on upgrade. A library imported with nowhere to hand files back arrives switched off.
- **Weir hears when Sonarr or Radarr imports a file** (#652). Point their Connect › Webhook at Weir (Settings › Media managers shows how) and History says "Imported by Sonarr", with the time and where it went. When the manager copied or hardlinked the file, Weir removes its own hand-back copy, but only while that copy is still exactly as Weir wrote it: never a download, never the manager's own file.
- **Deluno can tell Weir what became of a hand-off**: imported, or not imported for good. A copy Deluno will not import is kept, and History says so. Weir advertises this as the `handoff-outcome` capability.
- **Cleanup › Unclaimed hand-backs**, off by default: removes Weir's own copies nobody imported after a window you choose (14 days to start), under the same "exactly as Weir wrote it" rule.
- **Held up because a manager is down? Weir says so.** "Waiting for Deluno, which is not answering. Weir will tell it this file is ready when it answers." The report goes as soon as the manager answers again.

## Fixes And Stability

- **Alerts are sent.** Channels could be saved and "Send test" worked, but no job ever produced an alert.
- **The leftover work file sweep runs.** It had a timer and nothing to do the work.
- **A held file is picked up when its wait ends**, not at the next scan up to five minutes later, and Arriving counts every wait down to a real moment.
- **A library file can be cleaned more than once**; a finished job no longer blocks the next request.
- **A library scan measures what Matroska files would save** instead of reporting nothing to reclaim (#648).
- **A disabled button looks disabled.**
- **The Library table's headings line up with their columns**; each sat one column to the left.

## Upgrade Notes

- **This release changes the database.** Migrations run on first start and add: what Weir has done to each library file, each cleanup job's interval, the link between imported libraries and their manager, and what each manager said about a hand-back; on first start every library without a rules profile is given one. A 3.2.0 database cannot be opened by 3.1.x, so take the backup the installer offers if you may want to go back.
- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top.
- Docker: `docker compose pull && docker compose up -d`.
- For integrators: `POST /api/v1/intake/handoffs/{source_key}/{handoff_id}/outcome` is new, authenticated with `X-Webhook-Secret` like the other hand-off routes, which are unchanged. The processing settings no longer carry `verbose_detection_logging`; a client that still sends it is not refused.
