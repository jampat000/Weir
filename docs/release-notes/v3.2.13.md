# Weir v3.2.13

Date: 2026-09-30

First run connects your media manager first, Settings' libraries are now called workflows and say plainly whether they are Weir only or linked, Weir takes its name from the computer it runs on, and the folder checks tell you when things are in sync and exactly what to change when they are not.

## What Changed

- **First run connects first.** Setup asks how downloads reach Weir: Deluno, Sonarr or Radarr, a download client, or neither. It connects and tests that, then offers Movies and TV workflows with their folders filled in from what it reports. Nothing is created until you press Finish.
- **Workflows, not libraries.** In Settings, the watched folder → output folder setups are now called workflows, so "library" means only your finished media. Each workflow is marked **Weir only** or **Linked to** its media manager. **Add workflow** asks which kind first. Media managers lists the workflows each connection feeds. A linked workflow describes its path in the media manager's own words.
- **Names come from the computer.** Weir is called after the computer it runs on ("Weir on RIG"), in the browser tab, the sidebar, alerts and System › About. Media managers and download clients are named after where they run ("Deluno on RIG", "qBittorrent on 10.1.1.51"). The Name fields are gone. In Docker, set `hostname:` in your compose file to choose the name.
- **Processing shows each file's steps as one animated flow**: checking, planning, writing, verifying and handing back. When a file finishes, fails or is rejected, its card stays a moment to show where it ended before it moves to Just finished.
- **New files appear on Processing live**, within seconds of landing, without reloading the page.
- **Performance's wait and minimum size apply to every workflow.** Each workflow uses them unless you set its own, and its editor shows which value it is using.

## Fixes And Stability

- **Rejected files stay rejected.** A file your rules leave nothing to keep in is recorded as **Rejected**, with a plain reason naming the rule and the setting to change. It is no longer picked up again at every scan. Removing it from History asks what to do with its download.
- **The remove dialog asks first.** It opens with nothing chosen, and Remove stays off until you pick an option, so Enter can no longer delete a download by accident.
- **Browsers no longer fill your Weir sign-in into other services' forms.** Before, a saved Weir password could land in a media manager's API key field.
- **The folder checks tell the truth:**
  - A download client folder that isn't the watched folder no longer shows a green tick.
  - The output folder is checked for reading as well as writing.
  - A folder reached two ways, through a junction, symlink or mount, is recognised as the same folder.
  - When Weir can't see whether a media manager's folder matches, it says "not verified" and names both ways to fix it.
- **A stopped media manager reads plainly:** "Weir could not reach Deluno at …", with no technical error text.
- **qBittorrent 5.x connects.** Its new login answer was taken for a wrong password.
- **Weir-only workflows** no longer say a finished file is waiting for a media manager to import it.
- **Windows:** the tray asks the server to stop and waits for it. It no longer waits 10 seconds and then force-stops it on every restart, network-access change and update, so restarts are quicker and work in progress is closed properly.

## Upgrade Notes

- The database is upgraded automatically on first start. Workflows that were left at the old default wait or minimum size now follow Performance, and ones you set yourself keep their values.
- Existing media manager and download client connections are renamed after their address on first start. Backups restore connections by type and address.
- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept.
- Docker: `docker compose pull && docker compose up -d`. To choose the name Weir shows, set `hostname:` for the service in your compose file.
