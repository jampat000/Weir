# Weir v3.2.15

Date: 2026-09-30

With Deluno 1.0.0-rc.23 or later, Weir checks where each of Deluno's download clients really saves, using Deluno's own path mappings, and says plainly what to change when a folder doesn't line up.

## What Changed

- **Deluno-linked workflows are checked end to end.** Deluno 1.0.0-rc.23 and later tell Weir where each download client saves for a library, and how Deluno's path mappings translate those folders. The workflow's Folder chain now shows, for each client and category, whether its downloads land in the watched folder. When one doesn't, it names the client, the category, the folder and exactly what to change.
- **Deluno's path mappings are applied before comparing.** Weir checks the downloads folder and the cleaned-output folder as Weir sees them, not as Deluno does. When no mapping covers a folder, it says which one to add.
- The Deluno and download-client sections of the Folder chain no longer disagree about the same folder.

## Fixes And Stability

- In first-run setup, choosing **A download client** no longer labels a workflow linked to Deluno as "Linked to a removed media manager".

## Upgrade Notes

- No database changes: 3.2.15 opens a 3.2.14 database as it is.
- **With Deluno older than 1.0.0-rc.23:** Weir keeps showing these folders as "not verified", and says that a newer Deluno enables the check.
- **Deluno API key:** the key Weir uses needs Deluno's Imports permission. Deluno sets that up when it connects Weir itself. A key created by hand without it gets a plain message saying how to fix it.
- **Windows:** this is the first update that 3.2.14's updater installs. It waits until you quit or restart Weir, and stops Weir cleanly first. **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top; existing data is kept.
- **Docker:** `docker compose pull && docker compose up -d`.
