# Weir v3.2.3

Date: 2026-09-23

This release stops Weir listing files that no longer exist.

## Fixes And Stability

- **A file that is gone stops being listed, including one a media manager handed over.** Since 3.1.3 Weir forgets a waiting, held or failed file once it has been gone from the watched folder for ten minutes, but only if a scan had seen it. A file a media manager hands over is recorded the moment it arrives, before any scan sees it, so when such a file was deleted its row stayed on Processing and History for good: "stuck", "waiting", or "cancelled, queue it again", for a file that no longer existed. Weir now judges those rows too, counting the ten minutes from when the row was last written. A cancelled hand-off whose file is gone is forgotten as well, since Weir never started it. A path that is now a folder on disk is kept, as is any file with a pass queued or running, and outcomes Weir reached (processed, passed through, rejected, skipped) stay as history. Each file forgotten gets one Activity entry saying why.

## Upgrade Notes

- No database changes: 3.2.3 opens a 3.2.2 database as it is.
- Nothing a media manager reads has changed.
- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top.
- Docker: `docker compose pull && docker compose up -d`.
