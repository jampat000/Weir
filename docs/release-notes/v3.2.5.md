# Weir v3.2.5

Date: 2026-09-24

This release lets you keep the original file after a library clean, makes the Processing progress bar move smoothly instead of jumping, and closes out a wide pass on security, performance and everyday usability across the app.

## What's New

- **Keep the original after a library clean.** A new per-library setting, off by default, moves the pre-clean copy into an originals folder (`.weir-originals` inside the library by default, or a folder you choose) instead of deleting it once the cleaned file is safely in place, so a removed track can be recovered without downloading the title again. The originals folder is excluded from the library scan whether the setting is on or off. (#735)
- **A smooth, moving progress bar.** Processing keeps a file's percent, stage and message in memory and pushes it to the browser as it happens, so the bar moves continuously instead of jumping every couple of seconds.
- **"Download again" is back in Library.** A file missing a track your rules would now keep offers to download it again, with a confirmation and a result shown afterwards.
- **History includes library cleans.** Downloads and library cleans now show together in one list, each with its own detail, and a skipped clean gets its own group instead of counting as failed.
- **Finished files can be processed again.** History adds a "Process again" action for files that are finished, cancelled or rejected; Weir refuses to requeue one whose original has since left the watched folder, with a plain reason.
- **Library paging.** The Library screen now pages through files with Previous/Next and an accurate count, instead of stopping at 200.
- **No default subtitle.** Choose tracks lets you clear a chosen default subtitle.

## Fixes

- **A TV season pack now reports every episode, not just the first to finish.** A hand-off of several files told your media manager it was done as soon as any one file finished, so the rest were processed but never reported. Weir now reports each hand-off exactly once, after every file in it is done.
- **A movie folder with more than one film is no longer emptied.** Removing a finished film used to delete its whole folder, so a collection pack or a shared "movies" folder lost every other film in it. Weir now removes only the file, and keeps the folder, whenever anything else in it is a video.
- **Removed-track history survives a restart.** It was being kept in memory only, and was lost every time Weir restarted.
- **Cancelling one file in a season pack no longer leaves the rest stuck.** The hand-off now re-checks whether it is ready to report as soon as a cancelled file settles it.
- **System › Backups says what a restore actually brings back**, instead of an inaccurate description.
- **A failed update check shows as failed**, not a misleading green tick.
- **Update from the tray on a manually staged install opens the right page**, instead of a Settings tab that no longer exists.

## Security

A wide security pass closed a number of gaps across the server, media-manager connections, the Windows tray and the Docker image. In plain terms:

- A crafted, deeply nested webhook payload could crash the whole server. Requests are now limited in nesting depth, number size and body size.
- Weir now only answers requests for hosts it recognises, configurable for a reverse proxy, with an exception for trusted proxies only.
- Setting Weir up for the first time from another device, or in Docker, now needs a one-time setup code instead of trusting whoever gets there first.
- Repeated wrong sign-in attempts on one account are slowed down, on top of the existing per-address limit.
- Connections to media managers and TMDb are pinned to a checked address and never follow a redirect.
- A hand-off's webhook secret is now tied to the connection it belongs to, so one connection's secret can no longer act on another's hand-offs.
- The Windows data folder is now locked to the account that owns it, and stored credentials use their own encryption key instead of sharing one with sign-in sessions.
- The Docker image pins its tool and base-image versions, runs its files as non-root, and refuses to start as root.
- Library, restore and tool-lookup folder paths are checked against a list of unsafe locations before Weir touches them.
- Exported activity history can no longer be opened as a spreadsheet formula.

Full details are in GitHub Security Advisories, published alongside this release.

## Performance

- **The Library screen loads without scanning its whole table**, cutting its slowest requests by more than half in testing.
- **Scans and cleanup no longer hold up new files.** A library scan or maintenance sweep used to be able to block a file's own processing, and vice versa; both now run independently.
- **Activity and Logs searches are faster**, thanks to internal database improvements.
- **Responses are compressed** where a browser supports it.
- **Weir becomes reachable as soon as it starts**, instead of waiting for startup recovery to finish first; processing itself still waits for recovery.
- **Lower idle memory and CPU use**, from a leaner memory setting and less frequent background checks when nothing has changed.

## Usability

- **Plain-language errors everywhere.** No more raw status codes or server internals on screen; a panel whose data failed to load says so instead of looking empty.
- **Confirmations are in-app dialogs**, not the browser's own pop-ups.
- **Keyboard and focus fixes** across Settings, dialogs and the schedule grid, including a schedule you can fill in with arrow keys.
- **Every Settings panel says how it saves** — as you go, or only on Save — and asks before you leave unsaved changes.
- **Clearer wording throughout**: "media manager" instead of "app" or "connection", "alert" instead of "notification channel", "profile" instead of "rule set".
- **Narrow screens no longer scroll sideways**; tables stack into readable rows instead.
- **First run is quicker**: a confirm-password field, straight sign-in once your account is created, and a "what's next" screen pointing at tracks, media managers and existing libraries.

## Upgrade Notes

- **This release changes the database.** Migrations run on first start and add: which connection a hand-off belongs to, the kept-original setting, per-file tracking for season-pack hand-offs, and several performance indexes. A 3.2.5 database cannot be opened by 3.2.4 or earlier.
- **Reverse proxy by domain name:** add the domain to `WEIR_ALLOWED_HOSTS`, or Weir refuses the request.
- **First-run setup from another device, or in Docker:** read the one-time setup code from `docker logs` or the `setup-code` file in Weir's data folder.
- **A media-manager kind with no connection at all, and no instance-wide webhook secret, now refuses its webhook.** An existing connection is unaffected, even one with no secret of its own — it keeps working, with a warning shown in Settings.
- **The originals folder (`.weir-originals` by default) is excluded from every library scan**, whether or not "keep the original after cleaning" is turned on.
- **Windows: the data folder's permissions are tightened** to the account that owns it, and stored API keys move to their own encryption key automatically. If you downgrade after this upgrade, a key saved since the upgrade needs to be entered again.
- **Docker refuses to start as root:** `WEIR_PUID`/`WEIR_PGID` of `0` now stops the container with a clear message.
- **Restoring a configuration backup refuses the whole restore if any library in it is invalid**, instead of applying it partially.
- **`WEIR_ENV` now defaults to `production`** when it isn't set.
- Internal: several large server source files were split by concern; no behaviour change.
- Windows: **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top.
- Docker: `docker compose pull && docker compose up -d`.
