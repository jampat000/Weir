# Weir v4.0.0

Date: 2026-10-03

Weir has a new look, and a Dashboard that shows your files moving through it as it happens. It now matches Deluno, shows a poster beside each title, has a System view that reads this computer, and gives every library file one clear status. This is a major version because pages moved and were renamed. Nothing was removed from the API, and your settings and files are kept.

## Before You Upgrade: What Moved

- **Settings is now Setup,** in four areas: Workflows, Connections, Rules and Performance. What was on the old Settings sections moved to these, or to System.
- **Processing is now the Dashboard,** at the same address.
- **History is now Activity,** at `/activity`.
- **Old links and bookmarks still work.** A link to `/history`, to an old Settings section, or to one of the old Processing tabs opens the same thing in its new place, with its filters.
- **One address now means something different.** `/activity` used to open System › Logs. It now opens the Activity page. The log is at System › Logs.
- **Rules › Metadata & artwork is gone.** A saved TMDb key is no longer used. See Posters and original languages.
- **The API only grew.** Everything new is listed under "For anyone using the API". Three routes are deprecated and keep answering.

## What Changed

### A new look that matches Deluno

- **Weir and Deluno now look like one family.** The same deep blue-black surfaces, one blue accent, the same rounded cards, and Inter as the typeface. Dark is still the default, and light keeps the same look.
- **A new side menu.** It has the Weir mark and groups called Live, Your library, Setup and Weir. Your own name and the version are at the foot, with Change password and Sign out, and the computer Weir runs on is shown under its name. The menu remembers in this browser whether you folded it.
- **A header on every page.** It has the page title, Pause and Resume, and the light and dark switch. A pill appears only when something is wrong: "Paused until ..." (it says how the pause ends) or "Can't reach Weir".
- **Each page's own controls sit on the title line.** Tabs, filters and buttons share the line with the page title. When they do not all fit, the filters fold into a **More** menu instead of scrolling or being cut off. The row of tabs is never squeezed into More.
- **Every page uses cards.** Activity, Library, Setup, System, sign-in, first-run and the dialogs have the same panel look.
- **One set of controls.** Buttons, pickers and fields come in three heights and one style everywhere, and every control lines up with its title.
- **Removing something looks like removing something.** Red is only for removing, overriding or stepping outside normal running: the button that confirms a removal, a restore, signing out other sessions or clearing the log. Cleaning is normal work, so its confirmations are blue.
- **Tables stack on a small screen.** Activity rows take two lines on a phone so file names keep their width, and no table scrolls sideways on a tablet.
- **Each workflow has a colour** from the same six colours Deluno uses, given in the order your workflows are listed in Setup.

### Status colours mean one thing

Every status in Weir now has a meaning, and every meaning has one colour, on every page and in both themes. A dot or ring always sits beside words, so colour is never the only signal.

- **Green:** done. Matches rules, Cleaned, Already clean, Finished, Answering, In sync, a backup that worked.
- **Blue:** Weir's own work. A solid dot while it is working (Cleaning, Writing 52%, Analysing, Checking), a hollow ring while it waits or is still to do (Needs cleaning, Queued, Waiting for your media manager).
- **Amber:** needs you. Can't clean yet, On hold, Rejected, a slow connection, warnings.
- **Red:** broken or removed. Couldn't finish, Failed, Not answering, errors, a track that is removed, and the buttons that remove something.
- **Grey:** left alone. Left alone, Skipped, Off, a file in Activity's Kept list, plain information.
- **Gold:** space saved, and only the figure ("1.2 GB saved"). It is a different colour from amber.

Tracks follow the same rule: a kept audio or subtitle track reads green (done) and a removed one red (removed), wherever tracks are shown (a file's story, the Library, Rules' "Try on a file" and a log entry's details).

The Pipeline's five lanes use neutral colours of their own that are never one of these, so a lane is never mistaken for a status.

**Waiting for your media manager.** A file Weir has cleaned that its media manager has not yet taken back reads "Waiting for your media manager". It is Weir's work still to do, not a problem: it is not counted in Needs you, it sits under In progress in Activity, and it sorts with In progress.

### The Dashboard: Live view

Processing is now called **Dashboard**. Its address is the same, so no bookmark breaks. It has two views, **Live** and **System**, next to its title.

- **The Pipeline.** Files move across Incoming, Queued, Analysing, Processing and Delivering as cards, and glide from one stage to the next. A finished file's card says **Delivered** for a moment, then its poster flies to Just finished.
- **Just finished.** A row of posters for what has just been done, each with a coloured status: green for what was done, with the space saved in gold ("1.2 GB saved") or "Already clean" for a file that needed nothing, amber for "Rejected", red for "Couldn't finish". Where there is room, it also says what was removed ("-1 audio / -7 subs") and when. Small windows show a slim colour strip and a short status instead. Chips narrow it to one workflow, and a workflow's tag on a poster opens that workflow in the Library.
- **Today.** What was cleaned, the space saved, and a two-hour chart in the colours Just finished uses. Hover the chart to read a value at any time. It counts whole files and uses the time zone you chose in Settings. It says so when nothing finished in the last two hours.
- **Working on now and Next.** Each file being worked on, with its step and percent, and a countdown to each workflow's next look at its folder, the library clean and the cleanup jobs.
- **Activity.** The latest lines in plain words. It shows only whole lines, says how many more there are, and links to the Activity page.
- **Needs you.** Files that need a person are grouped by what went wrong: not in a language you keep, failed while writing, stuck, skipped by a workflow rule. Each file has its own **Try again**, **Process again** or **Check again**, **Remove...** and **Open**. When nothing needs you it says "All clear". One count of files that need you is used in the side menu, on the Today tile and on the panel, so they always agree. Problems with Weir itself are a separate heading on the panel ("N things to fix in Weir") and are not added into that count.
- **Health.** Each workflow says why it is out of sync, or says plainly that Weir could not verify it. Each media manager and download client shows when it last answered and how fast. **Check now** reads every folder again and tests every connection.
- **Connections light up as Weir talks to them.** A row blinks blue while Weir asks, flashes green when the connection answers and red when it does not, and flashes green when a media manager calls Weir. Nothing flashes while the tab is hidden or when your system asks for less motion.
- **The work switch and the workflow picker.** Everything, New downloads or Library cleaning, and any one workflow, narrow every panel on the page together. Your choice stays in the address, so a link shares it. The picker is hidden when only one workflow is on. On a narrow header the switch becomes a picker.
- **It fills the window.** Live is as tall as your window and shares the height out to its panels. It shows only whole rows and says "and N more", with nothing cut off from 1366 pixels wide up to the largest screens. On a phone the panels stack and the page scrolls.
- **Wording.** Every status on a card is a few plain words, such as "Waiting to settle" or "Can't open it yet". The full sentence is in the card's tooltip, in Activity and in the file's story.

### The Dashboard: System view

- **This Weir.** A ring of how many of Weir's own checks pass, and tiles for the version and update, how long it has been running, how it was started (service, app or Docker), where it listens, how much room its data takes, how many browsers are watching live, how fast it answers, files at once, jobs today, restarts this week, Weir's own use of the computer and the files waiting for a slot.
- **This computer.** Live processor, memory and disk readings drawn as moving traces, with Weir's own share and its tools' share (ffmpeg and mkvmerge) shown apart. A reading Weir cannot get is left blank, never shown as zero.
- **Processing.** How much Weir's work is reading and writing now, and how fast it is going.
- **Storage.** Every drive Weir watches, works on or writes to, with its size, free space, the room Weir's own work files take, the space your workflows want kept free, and a forecast of when it fills.
- **Health.** Every check Weir can make, with problems first, each with **Fix it** and **Check again**. A workflow's whole folder chain opens from **Details**.
- **Connections.** Media managers and download clients grouped with an "N/M OK" count, when each was last checked and a **Test** button on each row, plus **Test all**.
- **Scheduled tasks.** Each workflow's scan and library clean, the cleanup jobs and Weir's own housekeeping, each with when it last ran, how it ended and a countdown to the next. Running tasks come first and blink blue, failed ones show why.
- **Log.** The latest lines of Weir's log. It opens on Problems when today had errors or warnings, and new ones appear at the top as they are logged.
- **Backups and tools.** **Back up now**, when the next backup is due, the newest backups with their sizes, where updating stands, and the ffmpeg and mkvmerge versions.
- **System has its own header.** It covers the whole of Weir and the computer, so the workflow picker only shows on Live. A workflow in the address is kept for when you go back to Live.

### Pages and navigation

- **The side menu is the way between pages; the tabs are the way within one.** Live holds Dashboard and Activity. Your library holds Library. Setup lists its four areas. Weir holds System.
- **History is now Activity.** The side-menu item, the page title and every link to it say Activity, and the page is at `/activity`. A bookmark or link to `/history` still lands there with its filters, `?show=attention` and all. The words Weir uses in messages and in System › Logs say Activity too: under **Logs › Log settings**, in **How long things are kept**, "Activity history" is now **Events** and "File history" is now **File activity**.
- **Activity is about files.** Its **Needs you** view lists exactly the files the side-menu badge counts, however long ago they stopped, and the badge opens it. The old "Needs you" chip, which meant only held files, is now **On hold**. Problems with Weir itself are no longer in that view; they stay on the Dashboard's Needs you panel, and failed jobs stay reachable in System › Logs.
- **Setup has four areas, each with tabs** (see Setup below).
- **System has four tabs:** About, Backups, Security and Logs. About is where it opens.
- **System › About, Backups and Security are laid out on a grid** with the controls on one height. Backups is two cards, the schedule and the backups themselves, and Save appears only once something has changed. Security has the sign-in card, the sessions, the protections as a checklist with anything needing attention first, and one Account card for the username and password.
- **A file's story says where the file is now** when it is on the Pipeline.

### Setup

- **Settings is now Setup, in four areas, each with tabs.** The side menu lists the areas, and the tabs are the way around inside one:
  - **Workflows:** File paths, Schedule.
  - **Connections:** Media managers, Download clients, Alerts.
  - **Rules:** Profiles, Playback devices.
  - **Performance:** Speed, Cleanup, Weir's timers.
- **File paths shows each folder on its own.** The first Workflows tab is now called File paths, and its table has a column for the folder Weir watches and another for the folder it cleans into, with the end of a long path kept visible. A workflow with no folders says "Cleans in place".
- **Priority is a number you can drag.** The up and down arrows are gone. Each workflow has a Priority number and a grip: drag it, or use Alt with the up or down arrow, to reorder, and it saves at once. When a file could go to more than one workflow, the higher one takes it.
- **Adding a workflow, media manager, download client or alert opens a panel beside the page**, with its first field ready to type in.
- **Connections are one row each.** A media manager or download client is a name, whether it answers, when it was last checked and its buttons on one line. A missing webhook secret is one warning above the list that names each manager, instead of the same sentence on every card, and an empty list says what the connection is for.
- **The workflow editor folds.** Identity and folders, and the folder chain, are open; media manager, intake rules, file readiness, output safety, capacity, failures, advanced and hours fold away, each showing what it holds. Browse sits beside its folder, and Save stays in view.
- **Rules is Profiles and Playback devices.** Playback devices is one list, a device to a row, with "Built in" for the built-in ones, and Save appears only once something has changed.
- **Speed, Cleanup and Weir's timers are full-width cards,** and Speed shows Save only once something has changed.
- **The time zone moved to System › About.** Schedule is now only each workflow's weekly hours, says which time zone they are read in, and links to About to change it.

### Library: one status for every file

- **Every library file has exactly one status,** and the counts add up to the files: **Needs cleaning**, **Cleaning**, **Matches rules**, **Can't clean yet** (still shared with a download, or unreadable) and **Left alone**. When more than one could apply, Left alone wins, then Cleaning, then Can't clean yet, then Needs cleaning, then Matches rules.
- **Chips across the top** for All and each status show a dot in the status colour and a count, and a status with no files shows a quiet 0. The chosen status goes in the address (`?show=`), so a view can be linked to. The words the old chips used still land on the slice they meant. The old **Cleaned** chip is gone: what Weir did to a file is a quiet note on its row ("cleaned 2 Oct", or "already clean"), never a status.
- **Why a file needs cleaning.** When Weir can say, a file that needs cleaning shows whether it is new since the last check, was replaced (the file on disk is not the one Weir last saw or cleaned), or its rules changed. The first scan of a library has nothing to compare with, so it gives no reason. Weir never guesses one.
- **One row per film.** A title with several files nests them and folds them, with a summary such as "2 need cleaning" or "5 match". Only a file that needs cleaning can be ticked. The reasons list for files that cannot be cleaned yet sits in the Files card's header while that status is chosen.
- **The header makes room.** The search is a magnifier until you use it, Library setup is a gear, and the workflow picker sits in the Files card. Library opens the library you last picked in this browser when the address names none.

### Tables you can arrange

- **Drag a column heading to put the columns in the order you want,** or press Alt with the left or right arrow on a heading. Click a heading to sort by it, and click again to reverse. An arrow shows which way. Activity's file list, the Library's files and Logs sort on the server, so the order holds across every page of results, not only the rows on screen.
- **Which tables.** Library, Activity (the files and the Kept list), Logs, Alerts, Cleanup, Weir's timers, Backups, Active sessions, the Dashboard's Scheduled tasks and Rules › Try on a file can be dragged and sorted. **Workflows** and **Choose tracks** let you move columns only, because the order of their rows means something there.
- **Weir remembers each table's order and sort** in this browser. **Columns** on the table's card has **Reset columns**, which puts the columns and the sort back the way they started.
- **Compact rows is gone.** Rows are one comfortable height; arrange the columns instead.
- **Dragging a workflow's priority is smoother,** and its grip is never left outlined or cut off.

### Logs: one log

- **One list instead of three.** Weir's events, its jobs and its server log are one list, newest first by default, under the day each thing happened. Each row says when, how it went (a red, amber, grey or green dot), where it came from (Event, Job or Server), what it is about (Processing, Scans, Cleanup, Library, Connections, Backups, Sign-in, Updates or Weir), the workflow when there is one, and what it was in a line or two. A row opens to everything its source recorded: an event's details, a job's attempts, what it was given and why it stopped (with Cancel pending, Recover result and Open the file in Activity), a server line's logger and exception.
- **Pick one source.** The chips **All**, **Events**, **Jobs** and **Server** choose one source at a time, each with how many rows it holds. The Category, Levels, Workflows and Time pickers then offer only what that source has rows for, and Workflows is hidden for Server, whose lines belong to no workflow.
- **Filters on the header, in the address.** The level picker shows Errors, Warnings and Info, each with its count and colour, and a search narrows the list further. Each applies as you choose it, with no Apply button, and the address holds them all, so a view can be linked to. **Refine** holds what only some rows have: an event's type, result and cause, a job's status, and server lines with a stack trace. Older `?show=events`, `?show=jobs` and `?show=server` addresses land on the matching source.
- **Sort it the way you need.** Click a heading to sort by time, level, source, category or workflow, either way. Weir sorts the whole log, not just the rows on screen, and paging stays correct under any sort: no row is repeated or skipped across pages. When the list is not sorted by time, each row shows its day with its time. Drag the headings to arrange the columns; **Columns › Reset columns** puts them back.
- **Log settings** is a button on the Log card. It holds **How long things are kept** and **Server diagnostics**.
- **Export** gives the rows the filters show as a spreadsheet or JSON, and the whole server log as the file it is. **Clear events…** clears the events and finished jobs, as Clear all history did, and nothing else. It asks you to type RESET.
- **Rows that arrive while you read wait for you.** While a row is open or you are further down, new ones wait behind "N new entries — show".
- **A failed job's next step points at its error** and at Try again in Activity, not at pages that no longer exist.

### Network access from System › About

- **Choose who can reach Weir from the page.** On the This PC card, an administrator picks **This PC only** or **Devices on my network**. Choosing the network first asks you to confirm, because other devices will be able to reach Weir's sign-in page.
- **It says where things stand.** The address another device would type, with a Copy button; "Waiting for approval on" the computer's name while Windows asks; "Restarting Weir" while only the restart is left; or "Blocked by Windows Firewall" with **Try again**. The page checks again every couple of seconds while a change is on its way.
- **On Windows the tray does the work.** It restarts Weir and, when Windows Firewall has no rule for Weir, raises the same Windows administrator prompt as its own menu item, on the PC itself. The rule covers Private and Domain networks only. If you decline the prompt, Weir still restarts for the network, because that is what you chose, and the page shows it as blocked until you try again. A choice already saved when the tray starts never raises the prompt.
- **On Docker and a bare install the page explains what decides it** (the port mapping, the `--host` option) and offers no choice, because Weir cannot change that from inside. Anyone who is not an administrator sees the state only.
- **Every change is written to Activity** as "Network access changed", with the administrator who made it.

### Posters and original languages

- **A poster beside each title.** On the Pipeline, in Just finished, in Activity, on the Library page and at the top of a file's story. Where there is none, you see the title's initials.
- **Where they come from.** Weir looks each title up once through Deluno's metadata service, which needs no account or key, and keeps the poster on this machine. Your browser only ever talks to Weir.
- **What is sent.** Only the title and year read from the file's name, or the ids (TMDb, TheTVDB or IMDb) that Deluno, Radarr or Sonarr gave Weir. Never a file name, a folder or anything about you. At most one lookup a title, spaced out, and Weir waits when the service asks it to.
- **Nothing to set up.** There is no switch for posters. To stop Weir contacting the service altogether, an administrator can start it with `WEIR_ARTWORK_GATEWAY_URL=off`: Weir then shows initials everywhere.
- **No more metadata provider or TMDb key.** Rules that keep a title's original language used to need a TMDb key typed under Rules › Metadata & artwork. That tab is gone: Weir gets each title's original language from the same Deluno metadata service lookup that finds its poster, so one lookup per title serves both, for films and for series. If the service doesn't know a title, the profile's audio preferences choose the tracks, as before.
- **Exact when it can be.** When Radarr or Sonarr report an import of a file Weir handed back, the ids they send give an exact match instead of a guess from the file's name.
- **Tidy.** A poster stays while any file of that title is in Weir. A month after the last one is gone, the poster and its record are deleted.
- **Credits.** **System › About** credits TMDb with its logo and says "TV metadata provided by TheTVDB", both linked.

### For Deluno and other media managers

- **Weir says which version it is.** `GET /api/v1/intake/capabilities` now includes Weir's `version`, so Deluno can show it. It is the release number (for example `4.0.0`). A Weir older than 4.0.0 sends no version, so treat a missing one as "older".
- **Deluno can send more about a title.** A hand-off may now carry the title, year, TMDb, TheTVDB and IMDb ids, season, episode and a poster address. Weir uses them to find the poster exactly. A field that is wrong is ignored and never fails the hand-off. A poster address is used only when it is on Deluno's metadata service, TMDb, TheTVDB or OMDb over https.

### Other changes you may notice

- **The Jobs table says less.** A queued, running, finished or cancelled job shows one short line, not a full sentence on every row. Messages about a real problem are unchanged.
- **"Already right - nothing to change" now reads "Already clean"** on Just finished, Activity and the Today chart.
- **Messages name the new places.** Weir's own sentences point at Setup tabs and at Activity, not at the old Settings sections or the History page.

## Fixes And Stability

- **Cleanup timers and Run now run every time.** Before, each cleanup job ran once, then every later timer and every **Run now** did nothing until the finished run was tidied away. Each run now lets go of its place when it ends, so the next one starts. Two runs of the same job still never overlap.
- **Job wording is plain.** Finished jobs no longer read as needing a review, and a job that needs nothing from you says so in a few words.
- **Dashboard cards no longer lose words.** A long workflow name, a writing speed or "Planning" is no longer cut off at 1538 pixels wide.
- **Needs you and the Today tile no longer disagree.** They counted different things before, and so did the side-menu badge. All three now show one number.
- **Needs you no longer misses failed files.** It reads them itself, so a long list on the Live page can't hide any.
- **A library clean no longer vanishes from Activity** when its entry happened to have a long detail.
- **Nothing on the Just finished row jumps** when a card says Delivered.
- **The System view can't stop Weir.** If reading a drive fails, Weir logs it, tries again at the next reading and keeps the drives it already knew.
- **The job queue's counters feed System's figures,** so job events and queue depth are no longer empty.
- **Exporting the log now includes every matching entry,** not only the rows that were on screen.
- **The log no longer repeats rows across pages** when events were stored without a fraction of a second.
- **Library no longer crashes** when the server sends no per-status counts.
- **Saving a Setup tab no longer wipes a draft** on another part of the page that was not saved yet.

## For anyone using the API

Nothing was removed or renamed, and no existing field changed meaning. Everything below is new, except the deprecation noted last, and the OpenAPI document (`apps/web/openapi/weir-openapi.json`) describes all of it.

- **New endpoints:**
  - `GET /api/v1/system/overview`: the facts System shows about this copy of Weir.
  - `GET /api/v1/system/stats`: the machine's load, memory and drives, with the last ten minutes of readings.
  - `GET /api/v1/system/tasks`: every scheduled task with its last run, last result and next run.
  - `GET /api/v1/system/log`: Weir's events, jobs and server log as one list, filtered by source, level, category, workflow, text and time, sorted, paged by a cursor, with the counts each filter choice would show (`counts.source`, `level`, `category` and `workflow`). `GET /api/v1/system/log/export` gives the same rows as a file. `/activity/recent`, `/processing/jobs/inspection` and `/suite/logs` are unchanged.
  - `PUT /api/v1/suite/network-access`: sets who can reach Weir, `this_pc_only` or `network`. It needs an administrator session and the usual CSRF token. Docker and a bare install answer `409` and say what decides there. `GET` on the same route now also says which way the running server listens, a saved choice it has not caught up with yet, the firewall state, the port, this PC's name and the addresses another device would type.
  - `GET /api/v1/artwork/posters/{poster_id}`: a poster image Weir already holds. It needs the same sign-in as the rest of the API.
- **New sort and paging parameters:**
  - `GET /api/v1/processing/files` (Activity's file list) takes `sort` (`file`, `status` or `when`), `direction` (`asc` or `desc`) and `cursor`, and returns `next_cursor`. Without them the order is what it has always been. A sort, direction or cursor it doesn't understand, or a cursor made for another sort or direction, is refused with `422`.
  - `GET /api/v1/system/log` and its export take `sort` (`time`, `level`, `source`, `category` or `workflow`) and `direction` as well, and `GET /api/v1/system/log` takes `cursor`.
  - `GET /api/v1/processing/libraries/{library_id}/library-files` takes `status` (`needs_cleaning`, `cleaning`, `matches`, `cant_clean_yet` or `left_alone`), and its existing `sort` now also accepts `status`.
- **New fields:**
  - `status` and `status_reason` on library files, and `by_status` counts on library totals. The statuses add up to the files.
  - `poster_url` on files, activity events, library files, kept files and the Activity page's cleans. It is null until a poster is found, and always null when an administrator has turned the metadata service off.
  - `last_answer_ms` and `last_used_at` on the media manager and download client lists.
  - `version` on `GET /api/v1/intake/capabilities`.
- **New frames on `GET /api/v1/activity/stream`:**
  - `system.stats`: a reading every second while a browser holds the stream open, and the newest one the moment a stream opens.
  - `system.tasks`: the whole task list each time a task starts or ends.
  - `system.log`: each new warning or error written to Weir's log.
  - `connection.activity`: Weir asking a connection, the connection answering or failing, and a media manager calling Weir.
- **A change to order.** `system.stats` can now be the first frame on the stream. Read frames by their name, not their position.
- **Deluno hand-off.** Optional `title`, `year`, `tmdbId`, `tvdbId`, `imdbId`, `season`, `episode` and `posterUrl` are read, and the request is not refused if one is malformed.
- **New setting.** `WEIR_ARTWORK_GATEWAY_URL` points Weir at another metadata service, or `off` for none.
- **Deprecated, not removed.** `GET` and `PUT /api/v1/processing/metadata-provider`, and `POST .../test`, still answer so older clients keep working, but there is nothing left to set. `GET` always says `provider: "deluno-gateway"`, `base_url: null`, `key_configured: false` and `artwork_enabled: true`; `PUT` accepts the old fields and ignores them; the test asks the metadata service whether it is up.

## Upgrade Notes

- **Your settings and files are kept.** The database upgrades automatically the first time the new version starts (migrations 0035 to 0038). It gains records for posters, for when each connection was last used and how fast it answered, for each time the server starts, and for why a library file needs cleaning. Nothing you set is changed.
- **Posters turn on by themselves.** After you upgrade, Weir starts asking Deluno's metadata service for the titles it already knows, a few at a time. There is no switch; start Weir with `WEIR_ARTWORK_GATEWAY_URL=off` if you don't want that.
- **Library statuses fill in on the next scan.** A file's "why" (new, replaced, rules changed) is only known once Weir has scanned the library after this upgrade and has an earlier scan to compare with, so the first scan shows no reasons.
- **A saved TMDb key is no longer used.** If you had typed one under Rules, Weir ignores it and asks Deluno's metadata service for original languages instead. You don't need to do anything; the key stays in the database, unread.
- **Where things moved.** Settings is Setup, in four areas. The Processing page is the Dashboard, and History is Activity. Old links still open the right place. Your layout choices for tables start fresh.
- **A custom proxy or firewall** that only lets Weir reach certain sites needs to allow Deluno's metadata service, for posters and for original languages.
- **Deluno:** with this version Deluno can read Weir's version from the intake capabilities. Nothing needs changing in Deluno for the upgrade.
- **Windows:** **Check for updates** in the tray or **System › About**, or install `Weir-win-Setup.exe` over the top. Existing data is kept. If you choose **Devices on my network** from System › About, Windows asks for administrator approval once, at the PC, to allow Weir through the firewall for Private and Domain networks.
- **Docker:** `docker compose pull && docker compose up -d`. Who can reach Weir is decided by your port mapping, as before, and System › About shows that without offering a switch.
